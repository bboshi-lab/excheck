# Git 컨벤션

## 작업 전 확인

1. 루트 `AGENTS.md`와 승인된 Plan의 범위·PR 분할·검증·배포 영향을 확인한다.
2. 현재 브랜치, 작업 트리, 기존 사용자 변경, 원격 `main`, 관련 열린 PR을 확인한다.
3. 승인되지 않은 변경이나 무관한 파일을 커밋하지 않는다. 사용자 변경을 덮어쓰거나
   삭제하지 않고, 변경의 출처가 불명확하면 확인한다.

## 브랜치

- `main`은 통합·배포 기준 브랜치다. 직접 변경하거나 직접 푸시하지 않는다.
- 소문자 영문 kebab-case로 목적을 표현한다.
  - `feat/<목적>`: 기능 추가
  - `fix/<목적>`: 오류 수정
  - `refactor/<목적>`: 동작을 유지하는 구조 개선
  - `docs/<목적>`: 문서·지침 작성
  - `test/<목적>`: 테스트 작업
  - `chore/<목적>`: 도구·환경·유지보수
- 브랜치는 합의한 하나의 리뷰 목적에 대응한다. 독립적인 여러 목적을 한 브랜치에
  몰아넣거나, PR 수를 늘리기 위해 무의미하게 분할하지 않는다.
- Cloud에서는 기존 체크아웃을 사용한다. 사용자 요청 없이 worktree를 추가하지 않는다.

## 커밋

- 형식은 `type(scope): 한국어 설명`이다. scope는 구분이 필요할 때만 사용한다.
- 타입은 `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `style`, `build`, `ci`, `perf`, `revert`를 사용한다.
- 제목은 실제 변경을 구체적으로 설명한다. `수정`, `완료`, `여러 개선` 같은 모호한 제목을 피한다.
- `docs`는 문서·지침에, `style`은 동작 변화 없는 코드 형식 변경에 사용한다.
- 서로 독립적인 변경은 별도 커밋으로 남긴다. 모든 파일을 마지막에 한 번에 커밋하지 않는다.
- 관련 파일을 경로로 명시해 stage하고, staged diff와 예상치 못한 파일 포함 여부를 확인한다.
- 예시:

  ```text
  docs(agents): 계획 승인과 문서 전용 검증 예외 정의
  docs(react): 컴포넌트 선언과 책임 분리 컨벤션 추가
  fix(checklist): 항목 저장 실패 시 입력 내용 유지
  ```

- 승인된 작업의 커밋·푸시·PR 생성은 별도 재승인 없이 진행할 수 있다.
- 기본은 일반 push다. force push, 이미 공유한 이력 재작성, 무관한 브랜치 삭제는
  사용자와 먼저 합의한다. commit hook이나 검증을 임의로 우회하지 않는다.

## 문서 전용 PR의 CI 생략

- `AGENTS.md`의 문서 전용 정의와 `docs/QUALITY.md`의 변경 판별을 따른다.
- CI가 변경 경로를 판별해 문서만일 때 앱 검사·빌드·배포를 생략하고 정상 체크 결과를 남긴다.
- `[skip ci]`를 붙이지 않는다. 실행 코드·의존성·스킬 스크립트·CI·배포 설정이 섞이면 전체 검사한다.
- PR에는 생략 대상과 대신 수행한 문서 검토를 기록한다. 생략을 검사 통과로 보고하지 않는다.
- 필수 검사나 보호 규칙을 우회하거나 완화하지 않는다. 판별 실패를 생략으로 처리하지 않는다.

## PR 작성과 자체 리뷰

1. 로컬 diff, 커밋 범위, 원격 기준 브랜치와의 차이를 확인한다.
2. 승인 범위, 설계, 실패 경로, 테스트, 보안·배포 영향 관점에서 자체 리뷰한다.
   문서 전용이면 경로·예시·상호 참조·모순·예외와 승인 범위를 검토한다.
3. 필수 검증을 수행하거나 합의된 생략·차단 사유를 기록한다.
4. PR 제목과 본문을 한국어로 작성한다. 제목은 커밋과 같은 타입 표기를 사용할 수 있다.
5. 본문에는 목적, 주요 변경, 검증 결과 또는 생략 사유, 자체 리뷰, 위험·제한을 포함한다.
   실제 관련 이슈가 있을 때만 연결하고, 존재하지 않는 이슈나 PR을 만들어 보고하지 않는다.
6. 자체 리뷰 의견과 사용자의 승인 리뷰를 구분한다. 사용자 명의의 승인이나 리뷰를
   대신 제출하지 않는다.
7. PR 링크를 전달하고 사용자 리뷰를 기다린다. CI 성공만으로 병합하지 않는다.

## 병합과 배포

- 사용자의 GitHub 승인, 최신 커밋의 필수 검사 통과, 미해결 변경 요청 부재를 확인한다.
- 승인이 현재 diff에 대한 것인지 확인한다. 승인 후 새 커밋이 있으면 다시 리뷰를 받는다.
- 문서 전용 검사 생략은 승인된 예외지만, GitHub의 보호 정책 우회 권한을 의미하지 않는다.
- 조건 충족 시 추가 대화 승인 없이 병합할 수 있다. 저장소가 허용하는 merge commit을
  기본으로 사용해 의미별 커밋을 보존한다. 기존 정책과 충돌하면 사용자에게 확인한다.
- 승인된 PR 병합 후 합의된 환경의 자동 배포를 허용한다. 배포 대상·권한을 임의로 바꾸지 않는다.
- 병합·배포의 실제 상태를 확인하고 보고한다. 실패 원인을 조사하되 승인 범위 밖의
  설정 변경이나 별도 운영 배포는 먼저 합의한다.
